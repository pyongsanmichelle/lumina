# Git運用マニュアル

## 1. ブランチ構成と役割
本プロジェクトでは **Git Flow** に基づいた運用を行います。

| ブランチ名 | 種類 | 役割 | マージ先 |
| :--- | :--- | :--- | :--- |
| **main** | 常設 | 本番環境。リリース済みのコードのみ管理。 | - |
| **develop** | 常設 | 開発環境。次期リリースのための最新コード。 | main (release経由) |
| **feature/** | 一時 | 新機能の開発。 | develop |
| **fix/** | 一時 | 通常のバグ修正。 | develop |
| **refactor/** | 一時 | 機能変更を伴わないコードの整理・リファクタリング。 | develop |
| **docs/** | 一時 | ドキュメントの作成・更新（コード修正なし）。 | develop |
| **chore/** | 一時 | ビルド設定、ライブラリ更新などの雑務。 | develop |
| **release/** | 一時 | リリース前の最終確認、微修正、バージョン付与。 | main, develop |
| **hotfix/** | 一時 | 本番環境で発生した緊急バグの修正。 | main, develop |

---

## 2. 命名規則の詳細

### 基本フォーマット
**種類 / 課題番号 - 概要** (英小文字, 単語間はハイフン)

* **例1:** feature/101-user-login
* **例2:** fix/205-header-layout
* **例3:** refactor/305-cleanup-auth-logic
* **例4:** docs/400-update-api-spec
* **例5:** release/v20260131-1

---

## 3. 各ブランチの使い分けガイドライン

* **feature/**: 新しい機能を追加するときに使用します。
* **fix/**: バグを修正するときに使用します。
* **refactor/**: 動作は変えずに、ソースコードを読みやすくしたり構造を整理したりするときに使用します。
* **docs/**: 設計書、README、API仕様書などのドキュメント類のみを更新するときに使用します。
* **chore/**: 依存ライブラリの更新、CI/CD設定、ビルド設定の変更など、アプリの機能に直接関係ない作業に使用します。

---

## 4. 基本的な開発サイクル

### ① 開発の開始
必ず develop ブランチから最新を取得して開始します。

```bash
git checkout develop
git pull origin develop
git checkout -b 種類/issue番号-summary
```

### ② コミットメッセージ
何をしたか明確に記載します。
* **Format:** `[issue番号] 内容（日本語可）`
* **Example:** `[#101] ログイン画面のバリデーション実装`

### ③ プルリクエスト (PR)
作業完了後、develop ブランチに対して PR を作成します。
1. レビュワーによる確認を受ける。
2. 承認後、develop にマージする。
3. **作業ブランチはマージ後に削除する。**

---

## 5. 禁止事項
* **main への直接コミット禁止**: 必ず release または hotfix を経由すること。
* **develop への直接コミット禁止**: 必ず作業ブランチから PR を経由すること。
* **巨大なコミット**: 1つの PR が大きくなりすぎないよう、こまめにマージを行うこと。
